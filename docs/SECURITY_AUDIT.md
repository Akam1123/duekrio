# Security audit — early access invoice workspace

**Reviewed:** 2026-09-25. **Scope:** the static React/Vite application, its CSV/JSON import and export paths, the checked-in GitHub workflows, the earlier Cloudflare Pages direct-upload deployment of commit `21141c6` at [duenara.pages.dev](https://duenara.pages.dev/), and the legacy GitHub Pages response. The Duekrio release and opt-in local workspace encryption require fresh build, live, and security verification before their status can be recorded here. This maps the 19 concerns in the [article supplied by the owner](https://medium.com/@madangopalboddu123/vibe-coding-got-you-hacked-here-are-the-19-vulnerabilities-nobody-warned-you-about-f0f899d61f78) to this product. The article is a source of audit topics, not an instruction to add features or claim that every example applies.

**Status key:** **N/A** means the vulnerable component does not exist in this release; it must be reassessed if the architecture changes. **Mitigated** means a specific control or absence was verified, not that exploitation is impossible. **Partial** means some controls exist and a residual risk remains. **Open** means a material exposure remains to address.

## Other controls and remaining priorities

- CSV upload is capped at 2 MiB. The import has a preview, reports skipped rows, requires acknowledgement of issues, and preserves existing data until confirmation. CSV export prefixes formula-like cells before writing spreadsheet files. These flows are in [App.tsx](../src/App.tsx) and [ledger.ts](../src/lib/ledger.ts). Spreadsheet programs can vary; users should still treat imported/exported files as untrusted.
- Corrupt browser data blocks edits and prompts for a raw download before restore or discard. Restoring a JSON backup validates it before replacing the workspace. Browser safety QA covered these paths, including an oversized backup and a valid restore.
- Optional exported-file encryption uses Web Crypto AES-256-GCM with a newly generated 16-byte salt and 12-byte IV for each backup and a PBKDF2-SHA256 key derived with 600,000 iterations from a user-entered passphrase of at least 16 characters. The app does not save or recover the passphrase. Earlier tests covered round-trip restore, fresh randomness, wrong passphrase, altered ciphertext, and rejected envelope metadata. The pending release also offers opt-in encrypted browser saves; verify that new path separately. A weak, reused, or exposed passphrase can still be guessed or stolen; exported CSV/plain JSON and raw recovery downloads remain readable. This code has not had an independent cryptographic review.
- GitHub [private vulnerability reporting](https://github.com/Akam1123/promiseledger/security/advisories/new) was enabled and its repository setting read back as enabled on 2026-09-25. It is for software vulnerabilities, not a private channel for customer data or privacy requests. An accountable operator and private privacy/contact route remain unresolved.
- GitHub repository settings were updated on 2026-09-25: a readback returned HTTP 204 for enabled Dependabot vulnerability alerts, `enabled` for automated Dependabot security updates, and `configured` for CodeQL default setup. The initial [CodeQL setup run](https://github.com/Akam1123/promiseledger/actions/runs/36154982957) reported two alerts against the preceding commit `8cdd14e`: [high, incomplete URL substring sanitization](https://github.com/Akam1123/promiseledger/security/code-scanning/2) and [medium, missing workflow permissions](https://github.com/Akam1123/promiseledger/security/code-scanning/1). The [CodeQL scan of `bbc209f`](https://github.com/Akam1123/promiseledger/actions/runs/36155723874) succeeded, and GitHub marked both alerts **fixed**. The changes use parsed, exact-origin URL comparisons and least-privilege CI permissions. No open CodeQL alerts remained at the 2026-09-25 readback; later changes require fresh review. The checked-in [Dependabot configuration](../.github/dependabot.yml) separately schedules version-update PRs. Review future alert and scan findings before release; [GitHub's public-repository security guide](https://docs.github.com/en/code-security/getting-started/quickstart-for-securing-your-repository) explains these features.
- New JSON backups include the sample-data marker and pending reconciliation flags; legacy backups remain readable, although their omitted marker cannot be recovered automatically. A stale second tab is warned and its browser writes are paused when another tab changes the workspace. It can export its local copy before reloading the latest saved version. The browser test covered two tabs with an open invoice draft. Web Locks serialize writes where supported; older browsers still rely on the storage-event and preflight checks, so a simultaneous write race cannot be ruled out on every browser.
- The older PromiseLedger repository retains its **GitHub Pages** workflow and old site for migration; the new Duekrio repository has no Pages deployment workflow. Neither Cloudflare Pages project is connected to automatic GitHub deployment. The earlier Duenara release was a manual direct upload of a tested `dist-hosted/` build for commit `21141c6` to its `main` production branch. A future Git push alone does not update either Cloudflare project. [Direct Upload cannot be converted to native Git integration](https://developers.cloudflare.com/pages/get-started/direct-upload/); same-project CI would need a separate, reviewed API-token workflow. Repository branch protection, Cloudflare account access controls, and future manual uploads need continuing review.
- The earlier hosted build used external JavaScript and CSS rather than executable inline HTML. Its generated `_headers` rule applied to `/*` on Cloudflare Pages static responses. Local browser QA checked the landing page, sample workspace, content pages, copy action, 404 response, accessibility, and browser errors. The earlier Duenara live release passed sample-board, mobile, and backup/restore smoke checks; root and privacy returned 200 with intended canonical/host copy and response headers. These checks do not verify the pending Duekrio release or local workspace encryption. Build the new host with `PUBLIC_ORIGIN=https://duekrio.pages.dev/` and inspect the generated links and live response after upload.
- Moving to a new hostname changes the browser **origin**. Existing `localStorage` entries on the old GitHub Pages or Duenara Cloudflare origins will not follow to Duekrio automatically. Keep both old apps usable for export, and restore through a validated JSON backup on the new host. Keep the current storage keys and backup formats compatible through the visual rebrand. Never silently overwrite or assume that an empty new-origin workspace means the old data is gone. This follows from [MDN's origin](https://developer.mozilla.org/en-US/docs/Glossary/Origin) and [localStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage) behavior.
- The legacy free GitHub Pages service is not intended or permitted for a commercial SaaS/online business under [GitHub's Pages limits](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits). Cloudflare Pages Free is the primary host. Recheck its current terms, limits, and **actual response headers** after each deployment.

## Limits of this review

This was source review, dependency advisory lookup, local browser flow QA, live Cloudflare root/privacy header checks, and a limited live browser smoke test. It was not a penetration test, an exhaustive check of every response, malware scan of every dependency, audit of the user's computer or accounts, or legal opinion. No software or hosting choice can guarantee zero breaches, data loss, claims, or liability. Reassess the N/A rows before adding authentication, server storage, payments, email sending, analytics, or third-party scripts.
