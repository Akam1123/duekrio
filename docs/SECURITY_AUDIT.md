# Security audit — early access invoice workspace

**Reviewed:** 2026-09-25. **Scope:** the static React/Vite application, its CSV/JSON import and export paths, the checked-in GitHub workflows, the prepared Cloudflare Pages build, and the then-current GitHub Pages response. This maps the 19 concerns in the [article supplied by the owner](https://medium.com/@madangopalboddu123/vibe-coding-got-you-hacked-here-are-the-19-vulnerabilities-nobody-warned-you-about-f0f899d61f78) to this product. The article is a source of audit topics, not an instruction to add features or claim that every example applies.

**Status key:** **N/A** means the vulnerable component does not exist in this release; it must be reassessed if the architecture changes. **Mitigated** means a specific control or absence was verified, not that exploitation is impossible. **Partial** means some controls exist and a residual risk remains. **Open** means a material exposure remains to address.

## Other controls and remaining priorities

- CSV upload is capped at 2 MiB. The import has a preview, reports skipped rows, requires acknowledgement of issues, and preserves existing data until confirmation. CSV export prefixes formula-like cells before writing spreadsheet files. These flows are in [App.tsx](../src/App.tsx) and [ledger.ts](../src/lib/ledger.ts). Spreadsheet programs can vary; users should still treat imported/exported files as untrusted.
- Corrupt browser data blocks edits and prompts for a raw download before restore or discard. Restoring a JSON backup validates it before replacing the workspace. Browser safety QA covered these paths, including an oversized backup and a valid restore.
- The prepared hosted build contains external JavaScript and CSS rather than executable inline HTML. The generated `_headers` rule applies to `/*` on Cloudflare Pages static responses; a local browser QA harness served the same policy and confirmed the landing page, sample workspace, five content pages, copy action, 404 response, accessibility checks, and no browser errors. The harness is not a substitute for testing Cloudflare's actual deployment. Rebuild with the **claimed** HTTPS hostname so canonical/OG links and the privacy disclosure describe the real site; inspect the generated external GitHub links before release.
- Moving to a dedicated hostname changes the browser **origin**. Existing `localStorage` entries on the old GitHub Pages origin will not follow automatically. Before redirecting or removing the old app, keep a way for existing users to export their old-origin data and restore it on the new hostname. Keep the current storage key and backup format compatible through a visible product rebrand, or provide an explicit migration. Never silently overwrite or assume that an empty new-origin workspace means the old data is gone. This follows from [MDN's origin](https://developer.mozilla.org/en-US/docs/Glossary/Origin) and [localStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage) behavior.
- The current free GitHub Pages service is not intended or permitted for a commercial SaaS/online business under [GitHub's Pages limits](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits). A commercial launch needs a host whose current terms allow this use. Verify the new host's policies and **actual response headers** after deployment.

## Limits of this review

This was source review, dependency advisory lookup, a header check of the existing live site, and local browser flow QA of both the app and proposed host policy. It was not a penetration test, a live Cloudflare Pages header verification, malware scan of every dependency, audit of the user's computer or accounts, or legal opinion. No software or hosting choice can guarantee zero breaches, data loss, claims, or liability. Reassess the N/A rows before adding authentication, server storage, payments, email sending, analytics, or third-party scripts.
